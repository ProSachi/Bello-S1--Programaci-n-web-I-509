Unidad I - Generalidades de Javascript

Semana 4: Funciones

Temas: Funciones en JavaScript: Funciones regulares, Parámetros y Retorno de valores.

Situación - La Máquina Expendedora y la Fábrica

Imagina una fábrica de automóviles. Sería ilógico e ineficiente que un solo ingeniero construyera todo el auto desde el chasis hasta la pintura en una sola secuencia larga de trabajo. En su lugar, la fábrica se divide en "estaciones" o "módulos": una estación ensambla el motor, otra pinta la carrocería, otra coloca las llantas.

En la programación, cuando escribimos todo el código de arriba hacia abajo en un solo bloque, creamos un script frágil y difícil de mantener (conocido como código espagueti).

Una función es como una de esas estaciones de la fábrica, o más simplemente, como una máquina expendedora:

  1. Le insertas monedas y un código (los parámetros).
  2. La máquina procesa internamente la solicitud (el cuerpo de la función).
  3. La máquina te entrega una lata de refresco (el retorno).

Las funciones nos permiten aplicar el principio DRY (Don't Repeat Yourself - No te repitas). Escribimos la lógica una vez, la empaquetamos en una función y la reutilizamos cientos de veces.

¿Qué son las Funciones?

Una función en JavaScript es un "bloque de código" que agrupa una serie de instrucciones para realizar una tarea específica. Le das un nombre, y cada vez que quieres que la tarea se ejecute, simplemente "llamas" a la función por su nombre.

¿Por qué usamos funciones?

  • Reutilización de Código: Evitas repetir el mismo código una y otra vez. Escribes la lógica una vez y la usas cuantas veces sea necesario. ¡Menos código, menos errores!
  • Modularidad: Divides tu programa grande en piezas más pequeñas y manejables (nuestras "mini-máquinas"). Cada pieza se encarga de una tarea específica, lo que facilita entender, probar y mantener tu código.
  • Legibilidad: Un programa con funciones bien definidas es más fácil de leer y entender, tanto para ti como para otros desarrolladores. Los nombres de las funciones nos dicen qué hacen.

Declaración y Llamada de Funciones

Para crear nuestra función necesitamos declararla, con un nombre. Luego, para "ejecutarla", necesitamos llamar o invocar la función.

Sintaxis Básica de Declaración (Función Regular):

function saludar() { // Abre la función 
    // Aquí va el "cuerpo" de la función: las instrucciones que realizará 
    console.log("¡Hola, mundo!"); 
    console.log("¡Bienvenido a JavaScript!"); 
} // Cierra la función

Palabra reservada: function

Nombre: Sigue las mismas reglas que las variables (camelCase, descriptivo, a menudo usando verbos como calcular, mostrar, validar).

Llamada o Invocación de una Función:

Para que la función haga su trabajo, tenemos que "llamarla" o "invocarla". Esto se hace simplemente escribiendo su nombre seguido de paréntesis (). 

function saludar() { 
    console.log("¡Hola, mundo!"); 
    console.log("¡Bienvenido/a a JavaScript!"); 
}

saludar();

Hoisting de Funciones

Una particularidad de las declaraciones de función es el hoisting. Esto significa que JavaScript "eleva" la declaración de la función al principio de su ámbito antes de ejecutar el código. Por lo tanto, puedes llamar a una función declarada con function antes de que su definición aparezca en el código.

Parámetros y Argumentos (Entradas)

Una función que solo hace una cosa (como saludar siempre igual) no es muy útil. Necesitamos que sea flexible. Para eso, le pasamos "ingredientes".

  • Parámetros: Son las "variables placeholder" que defines en la receta. Son los nombres de los ingredientes que la función espera recibir.
  • Argumentos: Son los valores reales que le pasas a la función cuando la invocas.

Parámetros

Los parámetros son variables especiales que se declaran en los paréntesis de la función. Actúan como marcadores de posición para los valores que la función necesita recibir cuando es llamada.

Cuando llamas a la función, le pasas argumentos. Los argumentos son los valores reales que se asignan a los parámetros. 

function presentarPersona(nombre, edad) {
    console.log(`Hola, mi nombre es ${nombre} y tengo ${edad} años.`); 
}

presentarPersona("Alicia", 25); 
presentarPersona("Roberto", 35);

Parámetros por Defecto

A veces, queremos que un parámetro tenga un valor predefinido si no se proporciona un argumento al llamar a la función. Esto se logra con los parámetros por defecto. 

function saludarPersonalizado(nombre = "Invitado") { // 'Invitado' es el valor por defecto
    console.log(`¡Hola, ${nombre}!`);
}

saludarPersonalizado("María"); // Salida: ¡Hola, María!
saludarPersonalizado();        // Salida: ¡Hola, Invitado! (no se pasó argumento, usa el defecto)

Retornar Múltiples Valores (indirectamente)

Una función solo puede devolver un valor. Sin embargo, si necesitas devolver varias piezas de información, puedes encapsularlas en un objeto o un array. 

function calcularOperaciones(a, b) {
    let suma = a + b;
    let resta = a - b;
    let multiplicacion = a * b;

    return {
        suma: suma,
        resta: resta,
        multiplicacion: multiplicacion
    };
}

let resultados = calcularOperaciones(10, 5);
console.log("Suma:", resultados.suma);               // 15
console.log("Resta:", resultados.resta);             // 5
console.log("Multiplicación:", resultados.multiplicacion); // 50

Ámbito (Scope) Básico de Funciones

Variables Locales: Las variables declaradas dentro de una función solo existen y son accesibles dentro de esa función. Son "locales" a esa función y no pueden ser vistas desde fuera.

El "Scope" o Ámbito es el "contexto" donde viven las variables.

Regla de "Las Vegas": Lo que se declara dentro de una función, se queda dentro de la función.

Acceso a Variables Globales: Las funciones pueden acceder a variables declaradas fuera de ellas (variables globales), pero no es una buena práctica depender demasiado de esto, ya que puede hacer el código más difícil de rastrear y probar. 

let variableGlobal = "Soy global"; 

function miFuncion() { 
    let variableLocal = "Soy local, solo existo aquí dentro."; 
    console.log(variableGlobal); // Sí puedo ver la variable global 
    console.log(variableLocal); 
}

miFuncion(); 
// Muestra: 
// Soy global 
// Soy local, solo existo aquí dentro. 

console.log(variableGlobal); // Muestra: Soy global
// console.log(variableLocal); // ❌ ERROR: variableLocal no está definida aquí fuera

Preguntas Frecuentes

¿Cuál es la diferencia exacta entre un parámetro y un argumento?

El parámetro es el "molde" o la variable vacía que pones cuando construyes la función (ej. function calcular(precio)). El argumento es el dato real que envías cuando la usas (ej. calcular(100)). El parámetro es la teoría, el argumento es la práctica.

¿Puede una función devolver (return) múltiples valores al mismo tiempo?

Estrictamente, una función solo puede ejecutar un único return y devolver un solo elemento. Sin embargo, ese elemento único puede ser un Arreglo (Array) o un Objeto que contenga múltiples datos por dentro.

Ejemplos Prácticos

Ejemplo 1: Función Simple (Sin Parámetros, Sin Retorno)

Imprime un encabezado de texto. 

function mostrarEncabezado() {
    console.log("-----------------------");
    console.log("   SISTEMA DE PAGOS    ");
    console.log("-----------------------");
}

console.log("Texto 1");
mostrarEncabezado();
console.log("Texto 2");

Ejemplo 2: Función con Parámetros (Sin Retorno) 

// Función para generar un correo corporativo

function generarCorreo(nombre, apellido) {
    // Normalizamos los datos 
    let correo = `${nombre}.${apellido}@empresa.com`.toLowerCase();
    console.log(`El correo generado es: ${correo}`);
}

generarCorreo("Santiago", "Yosa"); // santiago.yosa@empresa.com

Ejemplo 3: Función Completa (Parámetros y Retorno) 

function aplicarImpuesto(precioBase) {
    // 1. Validar el dato (siempre es buena práctica)
    if (precioBase <= 0) {
        return 0; // Salida temprana si el dato es inválido
    }
    
    // 2. Procesar
    const iva = precioBase * 0.19;
    const precioFinal = precioBase + iva;
    
    // 3. Retornar
    return precioFinal;
}

// Uso en el programa real
let totalLaptop = aplicarImpuesto(1000);
let totalMouse = aplicarImpuesto(50);

// Ahora puedo usar esos valores retornados para otra operación
let totalCarrito = totalLaptop + totalMouse;
console.log(`Total a pagar: $${totalCarrito}`); // 1249.5

Práctica Acompañada - Learning by Doing

Calculadora de Descuentos

Crear una función que reciba el precio de un artículo y el porcentaje de descuento a aplicar, y nos devuelva el valor final a pagar.

Paso a paso:

  1. Declara una función llamada calcularDescuento.
  2. Define dos parámetros entre los paréntesis: precio y porcentaje.
  3. Dentro de las llaves {}, calcula el valor del descuento multiplicando el precio por (porcentaje / 100). Guarda esto en una variable valorDescontado.
  4. Calcula el precioFinal restando el valorDescontado al precio original.
  5. Retorna el precioFinal usando la palabra clave return.
  6. Fuera de la función, invócala pasándole un precio de 500 y un descuento de 20. Guarda el resultado en una variable e imprímela.

Solución

// Declaración
function calcularDescuento(precio, porcentaje) {
    let valorDescontado = precio * (porcentaje / 100);
    let precioFinal = precio - valorDescontado;
    
    return precioFinal;
}

// Invocación
let pagoZapatos = calcularDescuento(500, 20);
console.log(`Total a pagar por los zapatos con descuento: $${pagoZapatos}`); // 400

Práctica B - Función: Conversor de Temperatura

Paso a paso:

  1. Define la función: Escribe una función llamada convertirCelsiusAFahrenheit.
  2. Define el parámetro: La función debe aceptar un parámetro, llámalo tempCelsius.
  3. Implementa la lógica: Dentro de la función, usa la fórmula (C * 9/5) + 32 para calcular los grados Fahrenheit.
  4. Retorna el valor: Usa return para devolver el resultado del cálculo.
  5. Prueba tu función: Llama a la función con diferentes valores y muéstralos en la consola.
    • console.log(`25°C son ${convertirCelsiusAFahrenheit(25)}°F`);
    • console.log(`0°C son ${convertirCelsiusAFahrenheit(0)}°F`);

Modularización

Podemos realizar una separación de responsabilidades a nivel lógico o físico. Hay cuatro pilares innegociables que debes tener en cuenta y transmitir al estructurar software modular:

1️⃣ El Principio de Responsabilidad Única

Un módulo (en este punto del curso, una función) debe hacer una sola cosa, hacerla bien y no hacer nada más.

Separar el cálculo matemático de la manipulación de la interfaz. Si la lógica matemática falla, no tienes que revisar el código de impresión visual.

2️⃣ Bajo Acoplamiento y Alta Cohesión

Acoplamiento Bajo (Lo ideal):

Qué tan dependiente es un módulo de otro. Si modificas la función calcularImpuesto, la función generarFactura no debería romperse. Para lograr esto, las funciones deben comunicarse estrictamente a través de parámetros y retornos, evitando usar variables globales.

Cohesión Alta (Lo ideal):

Qué tan relacionados están los elementos dentro de un mismo módulo. Todo el código dentro de validarUsuario() debe tratar exclusivamente sobre credenciales y permisos, no sobre la conexión a la base de datos de productos.

3️⃣ Funciones Puras vs. Efectos Secundarios (Side Effects)

Para que un módulo sea predecible y fácil de probar, debe tender a ser una "función pura".

  • Función Pura: Dado el mismo input (parámetro), siempre devolverá exactamente el mismo output (retorno), sin modificar nada fuera de su propio entorno.
  • Efecto Secundario (Side Effect): Cuando una función modifica una variable global, cambia algo en el DOM (HTML) o escribe en una base de datos.
  • Regla de diseño: Aísla los efectos secundarios. Ten funciones puras para la lógica, y funciones impuras separadas para alterar el sistema.

4️⃣ Encapsulamiento (El concepto de Caja Negra)

El desarrollador que utiliza un módulo no necesita saber cómo está programado por dentro; solo necesita saber qué datos requiere (parámetros) y qué le devolverá (return).

Si necesitas explicar cómo funciona el interior de tu función para que otro la pueda usar, tu encapsulamiento falló o tu código es ilegible.

Separación Lógica vs. Separación Física

Tenemos la separación lógica dentro del mismo archivo de js o podemos realizar la separación física y compartimentar en diferentes archivos.

Para la separación física necesitamos usar como herramienta principal los Módulos de ES6 (import / export), archivos y directorios. 

import { calcularImpuesto } from './matematicas.js';

❌ El Falso Modular (Física sin Lógica):

Si un estudiante tiene un archivo de 1,000 líneas de código espagueti y simplemente lo corta con unas tijeras en 4 archivos de 250 líneas unidos por import/export, no ha modularizado nada. Simplemente ha creado un "monolito distribuido". El código sigue acoplado, sigue siendo imposible de testear y ahora es peor porque tienes que saltar entre 4 archivos para encontrar un error.

✅ El Orden Correcto:

La separación lógica es obligatoria e innegociable desde el día 1 (separar en funciones puras e impuras). La separación física es una consecuencia que se aplica cuando el archivo crece demasiado o cuando una función lógica necesita ser reutilizada por otro script diferente.

Módulos ES6: type="module"

Para evitar problemas de CORS, por motivos de seguridad, los navegadores bloquean el uso de import/export a menos que le digas explícitamente al HTML que el archivo JavaScript es un Módulo. 

<script type="module" src="main.js"></script>

Al colocar type="module", el navegador entiende que main.js es el punto de entrada y que, de forma autónoma, irá a buscar y descargar otros.js por detrás sin necesidad de que nosotros llenemos el HTML de múltiples etiquetas <script>.

Named Exports vs Default Exports

Existen dos formas de exportar código: Named Exports (Exportaciones Nombradas) y Default Exports (Exportación por Defecto).

Named Exports:

Regla estricta: Al importar, DEBES usar exactamente el mismo nombre que se usó al exportar, y DEBES usar llaves {}.

Default Exports:

Regla estricta: Solo puede haber UN ÚNICO export default por archivo.

Nota: En un solo archivo podemos tener ambos tipos de exports.

Ejercicio Independiente

Misión: El Verificador de Contraseñas Funcional

Vamos a crear una función que valide si una contraseña es "fuerte" o no, y que nos devuelva un valor que podamos usar.

Instrucciones:

  1. Crea una función llamada validarContrasena
  2. La función debe aceptar un parámetro: contrasena.
  3. Dentro de la función, usarás los condicionales (if...else if...else) para implementar las siguientes reglas:
    • SI la contraseña tiene menos de 8 caracteres (contrasena.length < 8), la función debe return el string "Error: Contraseña demasiado corta.".
    • SI NO, PERO SI la contraseña es exactamente "12345678", la función debe return el string "Error: Contraseña insegura.".
    • SI NO (para cualquier otro caso), la función debe return el string "Contraseña segura. ¡Buen trabajo!".
  4. Prueba tu función: Llama a la función varias veces con diferentes contraseñas y guarda el resultado en variables.
    • let resultado1 = validarContrasena("123");
    • let resultado2 = validarContrasena("12345678");
    • let resultado3 = validarContrasena("passwordseguro123");
  5. Muestra los resultados en la consola.

Criterios de Logro Esperados:

  • La función validarContrasena está correctamente declarada y acepta un parámetro.
  • La función utiliza return en todos los caminos lógicos (en el if, else if y else).
  • El código no usa console.log dentro de la función, sino que retorna los valores.
  • Las llamadas a la función fuera de ella capturan el valor retornado y lo imprimen.

¿Debería Saber Algo Más?

Hemos aprendido la "declaración de función" clásica (function miFuncion() {}). Esta es la base. El siguiente nivel de maestría en funciones incluye entender cómo JavaScript las trata.

1️⃣ Las Funciones son "Ciudadanos de Primera Clase"

Esto significa que, en JavaScript, una función es solo otro tipo de dato, ¡igual que un Number o un String! Puedes hacer con ellas lo mismo que haces con las variables:

  • Asignarlas a variables: const miFuncion = function() { ... }; (Esto se llama Expresión de Función).
  • Pasarlas como argumentos a otras funciones: El callback en setTimeout o addEventListener.
  • Retornarlas desde otras funciones.

2️⃣ Expresiones de Función vs. Declaraciones

function saludar() {} (Declaración):

Es "elevada" (hoisted). El navegador la "mueve" al principio de tu código antes de ejecutarlo. Puedes llamarla antes de definirla.

const saludar = function() {}; (Expresión):

No es "elevada". Se comporta como una variable normal. No puedes usarla antes de declararla (Temporal Dead Zone).

⭐ Esta es la forma más predecible y recomendada en el código moderno.

3️⃣ Arrow Functions (Funciones de Flecha) (ES6 - Avanzado)

Son la sintaxis moderna y corta para escribir expresiones de función. Verás esto en el 99% del código moderno.

Expresión Antigua:

const sumar = function(a, b) { return a + b; };

Función de Flecha (Arrow Function):

const sumar = (a, b) => a + b;

💡 Es solo "azúcar sintáctico" (una forma más corta) para la misma idea. Lo dominarás con la práctica.
